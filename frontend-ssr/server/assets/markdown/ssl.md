本站对同一个域名分别通过 IPv4 和 IPv6 发起 TLS 握手，把两条链路的结果并列展示。这样能查出「桌面能访问、IPv6 用户打不开」这类只在单栈暴露的问题。

## 检测哪些项目

| 项目 | 说明 |
| --- | --- |
| 证书状态 | 是否有效、是否已过期 |
| 通用名 CN | 证书主体名称，判断是否与访问域名匹配 |
| SAN | 使用者可选名称列表，多域名证书主要看这一项 |
| 签发机构 | 颁发证书的 CA |
| 可达性 | 该协议栈下能否完成握手 |

## 为什么要双栈分开测

证书配置看似全局生效，实际上常出现两侧不一致：CDN 只给 IPv4 回源节点部署了证书、Nginx 的 IPv6 `listen` 段漏配证书、或 IPv6 侧走的是另一套负载均衡。只测 IPv4 会漏掉这些。

## 常见失败原因

1. 服务器已开启 IPv6，但防火墙或安全组没有放行源地址为 `::/0` 的 443 端口。
2. IPv6 虚拟主机未配置证书，参见 [Nginx 开启 IPv6](/doc/server/nginx_ipv6)。
3. 证书链不完整，浏览器侧校验失败但服务端看起来正常。
4. SAN 未包含当前访问域名，或客户端系统时间偏差导致误判过期。

先确认站点是否真的支持 IPv6，可用 [IPv6 网站检测](/ipv6webcheck)；解析是否正确用 [DNS 查询](/dns) 核对。
