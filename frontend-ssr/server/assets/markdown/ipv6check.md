## 先分清：你要检测的是哪一个 IPv6

「IPv6 检测」听起来是一个问题，其实是两个彼此独立的问题：

- **我这条网络支不支持 IPv6**：运营商有没有分配 IPv6 地址、本机是否优先走 IPv6。取决于宽带、光猫、路由器和操作系统，与你要访问的网站无关。
- **某个网站支不支持 IPv6**：域名有没有 AAAA 记录、服务有没有在 IPv6 地址上监听、防火墙有没有放行。取决于站长，与你的网络无关。

一侧通过、另一侧失败是常态：本机有 IPv6 地址，不代表某个老站点能被 IPv6 访问；网站双栈配置完好，也不代表你家的宽带已经下发 IPv6 前缀。先把问题归到正确的一侧，才不会在错误的方向上反复改配置。

## IPv6 检测和 IPv6 测试有什么不同

搜索里「IPv6 检测」「IPv6 测试」「IPv6 测试网站」经常混着用，落到操作上其实是三件事：查本机网络是否拿到 IPv6 地址、测某个域名能否通过 IPv6 访问、以及找一个能反复拨测的在线工具。前两件分别由首页和 [网站 IPv6 检测](/ipv6webcheck) 完成，本页负责把三类意图分到对应工具，避免用错方法得到相反结论。

如果只是想找一个打开就能出结果的 IPv6 测试网站，直接按上面的表格选：查本机用首页，查域名用网站 IPv6 检测，查端口用 IPv6 TCPing。三者都免费、无需注册，可以反复测。

## 检测不通过时，按现象找原因

| 现象 | 优先检查 | 对应文档 |
| --- | --- | --- |
| 本机没有 IPv6 地址 | 光猫 / 路由器是否开启 IPv6、运营商是否下发前缀 | [个人宽带如何开启 IPv6](/doc/user/enable_ipv6) |
| 有 IPv6 地址但系统总走 IPv4 | 操作系统的前缀策略 | [Windows 设置 IPv4/IPv6 访问优先级](/doc/user/ipv4_ipv6_prefix_precedence) |
| 网站有 AAAA 记录仍无法通过 IPv6 访问 | 服务监听与防火墙，而不是 DNS | [网站开启 IPv6 的三种方式](/doc/server/website_enable_ipv6) |
| Nginx 配了 IPv6 仍连不上 | `listen [::]:443` 与证书是否同时配置 | [Nginx 开启 IPv6](/doc/server/nginx_ipv6) |
| 云服务器 IPv6 不通 | 控制台分配地址、安全组是否对 `::/0` 放行 | [腾讯云 CVM 开启 IPv6](/doc/server/tencent_cloud_cvm_ipv6) |
| 部分节点通、部分节点不通 | 中间链路或 CDN 节点未覆盖 IPv6 | [IPv6 TCPing](/ipv6tcping) |

一个最常见的误区：**只添加 AAAA 记录就认为网站已支持 IPv6**。发布一个无法连通的 AAAA 记录，会让偏好 IPv6 的客户端先等待超时再回退到 IPv4，比不加更慢。判断「支持」必须同时满足 AAAA 记录、服务监听、防火墙放行三件事，详见 [如何确认一个网站是否开启 IPv6](/doc/server/ipv6webcheck)。

## 命令行与代码里的 IPv6 检测

浏览器工具给出的是当前网络路径的结果，脚本和抓包能覆盖更多环节：

- `curl -4` / `curl -6` 分别强制走两个协议栈取回出口地址，见 [curl 获取公网 IPv4 / IPv6 地址](/doc/user/cmd_getip)；
- 需要在程序里判断客户端走的是哪个协议栈时，见 [JS 检查客户端网络是 IPv4 还是 IPv6 访问优先](/doc/server/check_userip_ipv4_ipv6) 与 [Python / Golang 获取公网地址](/doc/user/code_getip)；
- 排查丢包或 MTU 问题，用 [tcpdump 抓包分析 IPv6](/doc/user/tcpdump_ipv6) 和 [WireShark 分析 IPv6 包头](/doc/user/wireshark_ipv6)；
- ICMPv6 回显不通不等于服务不可用，原理见 [IPv6 Ping 检测原理](/doc/user/ipv6_ping)。

## IPv6 改造验收与合规检测

备案、等保或 IPv6 改造验收场景里，常见反馈是「已备案网站提示不支持 IPv6」「IPv6 检测不通过」。这类判定通常由监管或第三方平台按域名做一次性拨测，结果与探测节点所在的网络环境有关。收到提示后建议按三项自查：

| 检查项 | 用什么查 | 常见不通过原因 |
| --- | --- | --- |
| AAAA 记录 | [DNS 查询](/dns) | 只给 CDN 加了 AAAA、源站未动；记录尚未生效 |
| IPv6 访问 | [网站 IPv6 检测](/ipv6webcheck) | 服务未在 IPv6 上监听、安全组未对 `::/0` 放行 443 |
| 双栈证书 | [SSL 证书检测](/ssl) | IPv6 虚拟主机漏配证书、证书链不完整、SAN 未覆盖检测域名 |

「IPv6 检测证书」这类提示多半落在第三项：客户端在 IPv6 侧握手时拿到的证书与 IPv4 侧不一致，或 SAN 没有包含被检测的域名。这类问题改服务端证书即可，不需要动 DNS。

官方与第三方检测平台通常设有每日检测量上限，改造期间反复改配置、反复复测时未必够用。本站工具无需注册、可多节点反复自查，适合放在正式验收之前；最终结论仍以对应平台的检测结果为准。

## 常见问题

### 怎么知道自己的网络支持 IPv6？

打开首页即可看到本机的 IPv4 与 IPv6 出口地址，并通过双栈测试域名判定当前网络是 IPv6 优先还是 IPv4 优先。如果 IPv6 一行为空，通常是运营商未下发地址或光猫、路由器未开启 IPv6，与本机的网站访问无关。

### 网站怎样才算真正支持 IPv6？

需要同时满足三个条件：域名有 AAAA 记录、Web 服务在 IPv6 地址上监听了 80/443 端口、防火墙或云安全组对源地址 ::/0 放行了这些端口。只添加 AAAA 记录而服务未监听，是最常见的「假支持」。

### 本机检测和网站检测有什么区别？

本机检测回答「我这条宽带和操作系统能不能用 IPv6」，取决于运营商、路由器和系统前缀策略；网站检测回答「某个域名能不能被 IPv6 用户访问」，取决于站长的 DNS 记录、服务监听和防火墙。两者互相独立，一侧通过不代表另一侧通过。

### 已经加了 AAAA 记录，为什么 IPv6 还是访问不了？

优先检查服务端是否在 IPv6 地址上监听（如 Nginx 的 listen [::]:443）以及安全组是否放行 ::/0，再检查 IPv6 虚拟主机是否单独部署了证书。发布一个无法连通的 AAAA 记录会让客户端等待超时后才回退 IPv4，比不加更慢。

### 不同平台的 IPv6 检测结果为什么不一致？

各平台的探测节点分布在不同地域和运营商，CDN 调度、互联互通路径与安全组策略都会造成差异。个别节点失败多为中间链路问题，所有节点都失败才更像目标站点自身配置有误。建议用多节点工具看整体趋势而不是单点结论。

### 备案或验收时提示「网站不支持 IPv6」怎么办？

先按三项自查：用 DNS 查询确认 AAAA 记录、用网站 IPv6 检测确认双栈可访问、用 SSL 证书检测确认 IPv6 侧证书链与 SAN 正常。最常见的是只发布了 AAAA 记录却没有在 IPv6 上监听 443 端口，或 IPv6 虚拟主机漏配证书。官方与第三方平台通常有每日检测量上限，改造期间可用本站多节点工具反复自查，最终以对应平台的检测结果为准。
