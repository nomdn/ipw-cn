本站从多个节点同时请求目标网址，把各阶段耗时拆开并列展示，用于判断慢在 DNS、连接、还是内容下载。

## 指标含义

| 字段 | 含义 |
| --- | --- |
| 解析 IP | 该节点实际连到的地址，可看出 CDN 调度差异 |
| HTTP / HTTPS 状态码 | 两种协议分别探测，状态码不一致往往指向重定向或证书配置 |
| 总时间 | 从发起请求到内容下载完成 |
| 解析时间 | DNS 解析耗时 |
| HTTP 连接 | 建立连接、等待首字节的耗时 |
| 网页大小 / 下载速度 | 传输内容体积与实测速率 |

**总时间长但下载速度不低**，通常是内容体积大或首字节慢；**下载速度低**更偏向链路带宽或节点出口拥塞。

## 为什么各节点差别很大

节点分布在不同地域与运营商，CDN 命中情况、缓存是否过期、出口拥塞都会影响结果。看趋势比看单点数值有意义：如果只有某个节点明显偏慢，多半是该节点到目标的路径问题，而不是网站本身。

需要区分「端口通不通」与「页面快不快」时，配合 [TCPing](/tcping) 一起看；解析到非预期 IP 时用 [DNS 查询](/dns) 核对。
