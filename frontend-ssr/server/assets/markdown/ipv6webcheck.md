本站对同一域名分别从 IPv4 与 IPv6 发起检测，把「检测项目 / IPv4 / IPv6」并列展示。一个网站能被 IPv6 用户访问，需要同时满足三个条件，缺一个就会检测失败。

## 三个必要条件

1. **域名有 AAAA 记录**：DNS 能把域名解析到 IPv6 地址；
2. **服务在 IPv6 上监听**：Web 服务器配置了 IPv6 监听（如 Nginx 的 `listen [::]:443`）；
3. **防火墙放行**：安全组允许源地址为 `::/0` 访问 80 / 443。

只加一条 AAAA 记录是最常见的「假支持」：DNS 查得到，用户却打不开。

## 选 IPv6 测试网站时该看什么

一个能用来做验收自查的 IPv6 测试网站，至少要同时给出 IPv4 与 IPv6 两条路径的结果，而不是只回一句「支持 / 不支持」。本站按「检测项目 / IPv4 / IPv6」并列展示双栈状态码、DNS 解析时间与连接耗时：IPv4 正常而 IPv6 失败时，能直接看出是解析、连接还是 TLS 握手环节断掉。只有 AAAA 记录、没有实际连通性的「假支持」，在这种对比里会立刻暴露。

## 按失败原因对照

| 现象 | 优先检查 |
| --- | --- |
| IPv4 正常、IPv6 全失败 | 服务器未开启 IPv6，或安全组只放了 IPv4 |
| 443 端口不通 | 防火墙未对 `::/0` 放行 HTTPS 端口 |
| 证书相关报错 | IPv6 虚拟主机未部署证书，参见 [Nginx 开启 IPv6 SSL](/doc/server/nginx_ipv6) |
| 只有部分节点失败 | 中间链路或 CDN 节点未覆盖 IPv6 |

确认支持后，可在页面上添加 IPv6 访问标识，参见 [网站增加支持 IPv6 访问标识](/doc/server/ipv6_sign)。
