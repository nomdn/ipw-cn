## 和 ping、网站测速有什么不同

ping 走 ICMP，很多机房和云安全组默认丢弃，ping 不通不代表服务不可用；网站测速走完整 HTTP 请求，受页面大小、CDN、后端处理影响。TCPing 只对目标端口发起 TCP 三次握手，测的是「这条链路到这个端口通不通、往返多快」，正好卡在两者之间，适合排查服务本身的可达性。

## 结果字段怎么读

| 字段 | 含义 |
| --- | --- |
| 服务器 / 解析 IP | 发起探测的节点与实际连上的地址 |
| 发送包 / 接收包 | 探测次数与成功握手次数 |
| 丢包率 | 失败占比，比延迟更能说明链路是否稳定 |
| 最长 / 最短 / 平均时间 | 握手 RTT；最长与最短的差值反映抖动 |

平均延迟高不一定有问题（跨运营商、跨地域本就慢），但**丢包率非零**或**抖动特别大**通常值得继续查。

## 多节点结果不一致时

每个节点有独立的出口和运营商路径，个别节点超时可能是中间链路问题；**所有节点都不通**才更像目标服务故障。若只有部分节点解析到不同 IP，先用 [DNS 查询](/dns) 看看是否存在分线路解析或 CDN 调度。

IPv6 环境下的探测请看 [IPv6 TCPing](/ipv6tcping)，那一页专门讲 AAAA 记录与防火墙相关的问题。
